## 1. 概述

本数据库支撑《阅读笔记系统 V2.2》全部业务数据，与 Chroma 向量库协同：
- **SQLite**：结构化数据（书籍元信息、笔记、标签、状态、配置）
- **Chroma**：向量数据（`book_{book_id}` 集合存原书切片、`notes_all` 集合存笔记回流切片）
- **uploads/**：PDF 原始文件
- **logs/**：日志文件
- **config/**：配置与 Prompt 模板
- **backups/**：备份包

### 1.1 设计目标
1. **强一致性优先**：状态字段落库可查，支持断点续传、错误恢复、并发控制
2. **业务闭环可观测**：所有状态转换都有对应字段与日志
3. **软删除可恢复**：回收站机制，统一软删口径
4. **多版本可回滚**：AI 产物、Prompt 模板均保留多版本
5. **零外部依赖**：纯 SQLite，无需额外 DB 服务

## 2. 设计约定

### 2.1 命名规范
| 对象 | 规范 | 示例 |
|------|------|------|
| 表名 | 小写复数或名词短语，下划线分隔 | `books`, `note_tag_map` |
| 主键 | 字符串 UUID，固定 32 位 | `book_2026...` |
| 外键 | `{参照表名单数}_id` | `book_id`, `note_id` |
| 布尔字段 | `is_xxx` / `xxx_flag` | `is_indexed`, `soft_delete` |
| 时间字段 | `_at` 后缀，ISO8601 字符串 | `created_at` |
| 枚举字段 | TEXT + CHECK 约束，值用全大写 | `status`, `'UPLOADING'` |
| 预留字段 | 加 `_v1` 后缀，前缀备注 | `ext_v1` |

### 2.2 通用约定
- 主键统一为 **TEXT**（UUID 32 位无连字符），便于日志/trace 关联
- 时间统一为 **TEXT**（ISO8601 UTC，毫秒精度，如 `2026-10-15T08:23:45.123Z`）
- 业务字段非空时显式声明 `NOT NULL` + `DEFAULT`
- 软删字段统一为 `soft_delete INTEGER DEFAULT 0` + `deleted_at TEXT`
- 所有状态字段使用 CHECK 约束兜底，禁止脏数据
- 外键使用 `ON DELETE RESTRICT`，由业务层控制软删

### 2.3 主键策略
采用 **app-side UUID v4**，不依赖 SQLite 内建 autoincrement，便于分布式调试与日志关联：
```sql
-- 例如
'book_2026a1b2c3d4e5f67890a1b2c3d4e5f6'
'note_2026b2c3d4e5f67890a1b2c3d4e5f6a7b'
```

## 5. 详细表设计

### 5.1 books（书籍）

> 存储上传的 PDF 书籍元信息、状态机字段、构建结果。

| 字段 | 类型 | 非空 | 默认 | 说明 |
|------|------|------|------|------|
| `book_id` | TEXT | Y | — | 主键，UUID |
| `title` | TEXT | Y | — | 书名（从 PDF 元数据或文件名提取） |
| `author` | TEXT | N | NULL | 作者 |
| `file_path` | TEXT | Y | — | `{uuid}.pdf` 相对路径 |
| `file_size` | INTEGER | Y | — | 字节 |
| `total_pages` | INTEGER | N | NULL | PDFBox 解析后填充 |
| `status` | TEXT | Y | `'UPLOADING'` | UPLOADING/BUILDING/READY/REBUILDING/DELETING/DELETED/PURGED/CANCELLED/FAILED |
| `build_sub_stage` | TEXT | N | NULL | PARSE/RECOGNIZE/CHUNK/EMBED/INGEST |
| `build_progress` | INTEGER | Y | 0 | 0~100 |
| `error_code` | TEXT | N | NULL | 上次失败错误码 |
| `error_message` | TEXT | N | NULL | 上次失败中文提示 |
| `chunk_count` | INTEGER | N | NULL | 实际切片数 |
| `chapter_recognized_rate` | REAL | N | NULL | 0.0~1.0 |
| `embedding_model` | TEXT | N | NULL | 实际使用的模型 |
| `embedding_dim` | INTEGER | N | NULL | 向量维度 |
| `created_at` | TEXT | Y | — | ISO8601 |
| `updated_at` | TEXT | Y | — | ISO8601 |
| `last_ready_at` | TEXT | N | NULL | 最近一次变 READY 的时间 |
| `soft_delete` | INTEGER | Y | 0 | 0/1 |
| `deleted_at` | TEXT | N | NULL | 进入回收站时间 |
| `purge_at` | TEXT | N | NULL | 7 天后自动清理时间 |

**索引**：
```sql
CREATE INDEX idx_books_status      ON books(status) WHERE soft_delete = 0;
CREATE INDEX idx_books_purge_at    ON books(purge_at) WHERE soft_delete = 1;
CREATE INDEX idx_books_created_at  ON books(created_at DESC);
```

**CHECK 约束**：
```sql
status IN ('UPLOADING','BUILDING','READY','REBUILDING','DELETING',
           'DELETED','PURGED','CANCELLED','FAILED')
```

**示例**：
```sql
INSERT INTO books VALUES (
  'book_2026a1b2c3d4e5f67890a1b2c3d4e5f6',
  '认知觉醒', '周岭',
  'uploads/book_2026a1.pdf',
  12345678, 420,
  'READY', NULL, 100, NULL, NULL, 624, 0.87,
  'Doubao-embedding-text-240715', 1024,
  '2026-10-15T08:00:00.000Z','2026-10-15T08:05:00.000Z',
  '2026-10-15T08:05:00.000Z', 0, NULL, NULL
);
```

### 5.3 chunks（文本切片）

> **统一表**：通过 `chunk_type` 区分原书切片和笔记切片。

| 字段 | 类型 | 非空 | 默认 | 说明 |
|------|------|------|------|------|
| `chunk_id` | TEXT | Y | — | 主键，UUID |
| `book_id` | TEXT | N | NULL | FK → books；笔记切片为 NULL |
| `note_id` | TEXT | N | NULL | FK → notes；原书切片为 NULL |
| `chunk_type` | TEXT | Y | — | `'book'` / `'note'` |
| `content` | TEXT | Y | — | 切片文本 |
| `page` | INTEGER | N | NULL | 起始页码（笔记可为 NULL） |
| `chapter_path` | TEXT | N | NULL | 章节路径 |
| `chapter_title` | TEXT | N | NULL | 冗余便于调试 |
| `position` | INTEGER | Y | — | 在原书/笔记中的顺序号 |
| `word_count` | INTEGER | N | NULL | 字数 |
| `embedding_status` | TEXT | Y | `'PENDING'` | PENDING/DONE/FAILED |
| `embedding_batch_id` | INTEGER | N | NULL | 构建时的批次号（断点续传用） |
| `vector_id` | TEXT | N | NULL | Chroma 中的 id，便于反查 |
| `created_at` | TEXT | Y | — | ISO8601 |

**索引**：
```sql
CREATE INDEX idx_chunks_book       ON chunks(book_id, position);
CREATE INDEX idx_chunks_note       ON chunks(note_id, position) WHERE chunk_type='note';
CREATE INDEX idx_chunks_type_batch ON chunks(embedding_batch_id) WHERE chunk_type='book';
CREATE INDEX idx_chunks_status     ON chunks(embedding_status) WHERE embedding_status='PENDING';
```

**CHECK**：
```sql
chunk_type IN ('book','note'),
(chunk_type='book' AND book_id IS NOT NULL AND note_id IS NULL)
OR (chunk_type='note' AND note_id IS NOT NULL AND book_id IS NULL)
embedding_status IN ('PENDING','DONE','FAILED')
```

## 6. 向量层（Chroma）一致性说明

SQLite 是元数据权威，Chroma 是向量权威。两侧以 `book_id` / `note_id` 为业务键互查。

### 6.1 集合分布

| Chroma 集合 | 存储内容 | 元数据字段 | 与 SQLite 的关联键 |
|------------|---------|-----------|------------------|
| `book_{book_id}` | 原书切片 | `book_id`, `page`, `chapter_path`, `chapter_title`, `chunk_id` | `chunks.chunk_id` |
| `notes_all` | 回流笔记切片 | `note_id`, `chunk_id`, `note_title` | `chunks.chunk_id` ↔ `notes.note_id` |

### 6.2 一致性原则
- 写：先 SQLite 再 Chroma；Chroma 失败则 SQLite 回滚/标记失败
- 删：先 Chroma 再 SQLite；Chroma 失败需重试，SQLite 未提交
- 改笔记：SQLite 事务内暂存 → Chroma 删旧 → 嵌入 → Chroma 写新 → SQLite 提交
- 任何 Chroma 异常必须有 trace_id 与 usage_log 记录

### 6.3 校验脚本（每日任务）
- 抽样 N 本书，比对 `chunks.chunk_id` 与 Chroma 中同 id 的向量存在与否
- 差异超过阈值时报警

## 10. 已知约束与权衡

1. **单库 SQLite，不支持多写并发**：本系统设计为单用户本地部署，并发需求通过 WAL + busy_timeout 解决，不引入分布式 DB。
2. **TEXT 主键 vs INTEGER**：UUID 主键便于日志追踪与跨服务调用，但占空间大。当前 books 预估 50~200 本完全够用，无需分库分表。
3. **chunks 不存向量**：向量入 Chroma，chunks 仅存元数据与状态。这样 chunks 可作为向量库重建/校验的元数据源。
4. **note_chunks 复用 chunks 表**：通过 `chunk_type` 与 `note_id` 字段区分，避免双表维护。
5. **ai_tasks 与 ai_versions 拆分**：任务关注过程，版本关注产物。两者 1:N。
6. **chat_sessions 与 chat_messages**：单条问答的「存为笔记」通过 `source_ai_version_id` + `source_type=AI_QA` 落到 notes 表。
7. **缺失的人脸/账号字段**：本期明确单用户，不预留 user_id。
8. **审计日志不入表**：走文件 `logs/`，DB 仅存关键状态与聚合。
9. **chunks ↔ notes 表结构成环，但写入路径不成环**（已在 SQLite 3.50 实测）：
   - 表结构上 `chunks.note_id → notes.note_id` 与 `notes.source_chunk_id → chunks.chunk_id` 构成环
   - 但两条真实写入路径均不成环：
     - 摘录笔记的 `source_chunk_id` 指向**原书切片**（`note_id IS NULL`）
     - 笔记的回流切片 `note_id` 指向笔记，笔记不反向引用它
   - **删除互相引用的记录时**因 `ON DELETE RESTRICT` 会失败，必须在显式事务中
     用 `PRAGMA defer_foreign_keys = ON` 延迟到 COMMIT 统一校验（见 §7.3.4 永久删除笔记场景）
10. **建表 SQL 已通过实测验证**：可执行脚本见 `sql/0001_init.sql`，
    实测 `integrity_check = ok`、`foreign_key_check = 0 处违规`，
    50 题评测数据 / 8 个 Prompt 模板 / 6 个系统标签均已成功落库。
